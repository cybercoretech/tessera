# Tessera project website

This is the editable source for the Tessera project website. It is built with the Tessera CLI and its CSS-first Kit, in the Cybercore editor style (see the [site plan](../docs/superpowers/plans/2026-11-23-tessera-pages-site-plan.md)).

The page is laid out as the project open in an editor: an explorer rail (a
drawer below 1024px) lists the sections as files, and each section is a file
tab. The window bar holds Cybercore's shared theme chooser, which loads its
stylesheet, browser module, and theme catalog from `cybercoretech.github.io/kit`.
`styles/main.css` uses the chooser's variable names (`--bg`, `--cyan`, …) and
derives the Kit's `--ts-*` tokens from them, so every theme repaints the page.
If the shared assets are unavailable, the Cybercore dark fallback in
`styles/main.css` and `tessera.toml` applies.

| Path | What it is |
| --- | --- |
| `content/index.md` | The page: hero, live build, token playground, Kit explorer, get started, FAQ |
| `layouts/base.html` | Window bar, explorer rail, chooser, contact footer |
| `styles/main.css` | Site styles, themed scrollbars, mobile rules |
| `public/site.js` | Progressive enhancement: drawer, active file, typing, playground, Kit sheets |
| `public/backdrop.svg` | Editor backdrop, generated by `tools/make-backdrop.py` |
| `fixtures/night-shift/` | The real project shown in the live build section |
| `tools/stamp-build.py` | Writes `dist/build.json` (version, commit, file count, size) for the footer build line |

Everything works without JavaScript: the explorer is anchor links (the phone
drawer opens with `:target`), the Kit tree links to the guides, and all text is
static. `site.js` adds motion only when reduced motion is off.

The live build section replays a recorded `tessera build` of
`fixtures/night-shift`. To refresh it, run the build there and update the
terminal lines in `content/index.md`:

```sh
cd fixtures/night-shift && cargo run --manifest-path ../../../Cargo.toml -- build
```

Regenerate the backdrop with `python3 tools/make-backdrop.py`.

The footer uses Cybercore's shared `<cybercore-contact repo="tessera">`
component from `cybercoretech.github.io/kit/contact.js`. It reads contact,
social, and support links from the shared contact data, including the donation
options, and adds a direct link to Tessera's issue tracker. A direct contact
email remains as a fallback if the shared component cannot load.

From this directory, build the static site and stamp it with:

```sh
cargo run --manifest-path ../Cargo.toml -- build && python3 tools/stamp-build.py
```

The stamp writes `dist/build.json`, which the footer reads to show the Tessera
version, commit, page and file counts, and size. Build from a clean checkout of
`main` before deploying, or the commit shows a `-dirty` suffix. Without the stamp
the footer keeps a plain "built with tessera" line.

The command and toolchain sections quote real CLI output and config keys. When
the CLI changes, re-record them from a fresh `tessera new` project.

The generated files go into `website/dist/`. The site is deployed manually to [tessera-8gd.pages.dev](https://tessera-8gd.pages.dev/). Cloudflare assigned this hostname because Pages subdomains cannot be changed after project creation.

`wrangler.jsonc` binds the Pages project name to this directory's `dist/` output. Deploy manually from this directory with:

```sh
wrangler pages deploy dist --project-name=tessera --branch=main
```

CI does not publish the site automatically.
